# Deployable snapshot manifests

One JSON file per deployable DuckDB snapshot, each pinning exactly one
immutable S3 object version. Generated by
`scripts/build_snapshot_manifest.py`, consumed at task startup by
`scripts/fetch_snapshot.py`.

## What may live here

Structural identity only: byte size, SHA-256, S3 bucket/key/object version,
DuckDB library version, and the names of the relations the file must contain.

**Row counts, money totals and known-answer results must never be committed.**
They derive from protected source data and this repository is public. They live
in a private S3 object beside the artifact, named by the manifest's
`expectations_key`, and are fetched at startup. `fetch_snapshot` applies them
with the same fail-closed semantics as the hash check.

## Republishing

Snapshot objects are never mutated in place. A new artifact means a new object
version and a new manifest; rollback is reverting to the previous manifest,
which still names a live object version. Editing a manifest in place would
break that property.

## Where snapshots live

| | |
|---|---|
| Bucket | `dpic-prdw-snapshots` (ap-south-1, private, versioned) |
| Deployment prefix | `duckdb/` — the only prefix the #56 task role may read |
| Encryption | SSE-KMS under `alias/dpic-prdw-snapshots`, bucket keys enabled |
| Provisioned by | `infra/terraform/snapshot/` |
